##### REQ-5.1.4 SQL databases via drivers

WAVE reaches SQL databases through one Python driver per database type, chosen so that the same block runs on the WAVE server, on a remote host and through an SSH tunnel: PostgreSQL, MySQL / MariaDB, Oracle, SQL Server and SQLite.

**Driver Model**: Each database type binds to one driver behind one operational interface the SQL block uses: connect with the block's rows and TLS material, split a script the way that database's own tool splits it, translate `:name` placeholders into the driver's own parameter form, run statements with typed values, read a result's columns and types into a WAVE table, cancel a running statement, call a procedure with in and out arguments, load rows in batches with that database's insert and upsert statements, and read the catalog of tables and columns. PostgreSQL's, MySQL's and SQL Server's drivers are pure Python; Oracle's driver, the TLS layer SQL Server's needs, and SQLite, which WAVE bundles as its own build rather than taking the interpreter's, are compiled. The choice follows the remotability rule as it now stands: a remote host has nothing installed on it, and a compiled driver travels with the run (SQL-15). MySQL 8's default password exchange over a plain connection needs a small RSA step its driver takes from a compiled package; WAVE supplies that step itself so the block never fails on it. Because SQLite is WAVE's own build, it never depends on how a machine's Python was built.

**Nothing Installed on a Remote Host**: The remote worker already learns the host's Python version before it runs; it also learns the host's CPU and libc. For each compiled driver WAVE keeps the prebuilt builds for Python 3.10 through 3.14 on x86_64 and aarch64 with glibc and musl, pushes the one build that fits over the same channel the bundle rides, unpacks it into the run's own scratch directory on the host, and removes it with the rest when the worker stops. Nothing is installed, no package manager runs, and the host is left as it was found. A host outside the carried set fails the block before connecting, naming what it has and what WAVE carries. A guard test parses every piece of third-party code carried as source at the oldest Python the bundle supports, so a driver update cannot silently raise the host requirement. A driver that cannot be loaded on the machine where the block runs fails the block as unsupported, with a message that names the machine and the driver and carries the loader's own words; nothing is dialed.

**Connections**: Every block opens its own connection, does its work and closes it; there is no connection pool, no registry and no keepalive, because nothing persists a connection between blocks and a pool could not exist on a remote host where every block is its own process (SQL-1). Connect timeout bounds the handshake; Timeout bounds the whole block, and when it runs out the running statement is canceled on the database with that database's own cancel mechanism, so a runaway query does not keep running after the block has given up. Through an SSH tunnel the block dials the tunnel's far side the way Netcat does, by an implicit lookup of the open tunnel on the Local Port, and the TLS server-name check uses the far host.

**TLS**: Encryption is a toggle on the block with the trust rows the HTTP block already has: Verify Server Certificate, CA Certificate, Client Certificate and Client Key (SQL-8). Each driver negotiates TLS with the database's own protocol-level handshake and WAVE's certificate trust rule (REQ-4.5.16): a CA Certificate set on the block is the only certificate trusted, a blank one trusts the Additional Certificates and the public authorities chosen in Settings, any trusted certificate, root or intermediate, completes a chain, verification can be turned off for a lab, and a client certificate pair gives mutual TLS. With the toggle off the connection is plain; PostgreSQL in particular is asked for no TLS rather than trying it unverified. The toggle is off by default on PostgreSQL, MySQL, Oracle and SQLite, matching those drivers' own defaults, and on by default on SQL Server, which forces encryption unless told otherwise.

**Profile Binding**: The database profile carries what describes the target under the block's own names - host, port, database, username, password, the four trust rows and driver options - and nothing that is a choice or a per-request bound (SQL-14): the database type, the TLS toggle, the timeouts, Max rows, Batch size and the SQLite file stay on the block. A bound profile supplies values that the block's rows reference, as every profile binding does.

**Editor Services**: Two services on the WAVE server back the SQL editor. The syntax check parses a script with a dialect-aware SQL parser set to the chosen database and answers the lines and messages of what it could not parse, treating `:name` as a value placeholder; it runs after each typing pause on a body that holds no `{{ }}` and its findings never block a save or a run (SQL-10). The parser is lenient by design - it is built to translate SQL, not to police it - so a script it accepts can still be refused by the database, and the database stays the judge on Run. The catalog read connects with the block's own rows and the same trust rule, lists the tables and views with their columns for the schema the connection lands in, disconnects, and is cached per connection while the workbench holds the test open; it can be canceled while it connects or reads, and it never runs on its own (SQL-12).

**Errors**: The database's own words are never rewritten: a refused statement reaches the author as the database's own code and text, so that an error code found in the log can be looked up in one step. Connection failures, refused logins, timeouts, undefined placeholders and unsupported hosts each carry their own reason so that On error and a Try / Catch can tell them apart (SQL-5).

##### REQ-3.4.1.19 SQL drivers read no WAVE host configuration

The SQL block's drivers never take configuration from the WAVE host, so a connection behaves the same from every WAVE host and every remote host.

**Oracle connect strings**: WAVE never resolves an Oracle TNS alias and gives the driver no configuration folder, so the Oracle network files on the WAVE host, and the environment variables that point at them, are never read. A Driver options `dsn` is refused before connecting when it is a bare alias, any other form the driver would itself look up as an alias (a host and port with no service name, for example), a directory address (LDAP), or a configuration provider address. Each refusal says what to use instead: Host, Port and Service name, or the full connect descriptor. A full descriptor or an Easy Connect string is accepted; everything the connection needs lives in the test.

**Oracle address and TLS**: An address or a protocol given in Driver options must agree with the TLS toggle. With TLS on, the address uses TLS throughout and the block's certificate rows apply to it; with TLS off it does not use TLS. One that disagrees is refused before anything connects, so a block never reaches the database unencrypted while its TLS toggle is on, and never falls back to the trust list of the machine it runs on while the toggle is off.

**Session time zone**: An Oracle session uses the database's own time zone, as PostgreSQL, MySQL / MariaDB and SQL Server sessions do, never the WAVE host's. A test that needs a specific zone sets it in its own SQL.

**Client identity**: Every database that accepts a program name receives WAVE - PostgreSQL's application name, MySQL / MariaDB's program name attribute, Oracle's program and SQL Server's application name - rather than the path of the Python running the block. The machine name and the account the drivers report stay as they are, because they are true facts a database administrator uses to trace a connection. A Driver options entry of the same name still wins.

**SQLite**: SQLite runs on WAVE's own bundled SQLite, the same version on every WAVE host and remote host, never on the library the machine's Python was built with. It travels to a remote host like the other compiled drivers (SQL-15), in a build for every remote platform the block supports, so a remote host needs no SQLite of its own. SQLite takes two Driver options, `timeout` (seconds to wait on a locked file) and `cached_statements`; any other name is refused before the file is opened. A placeholder that has no value fails its statement with a message that names the placeholder and how to give it one. The Connected log line names its version. The bundled build needs glibc 2.28 or newer, or musl 1.2; a block on a machine where it cannot be loaded is refused before connecting, with a message that names the machine and carries the loader's own words.
