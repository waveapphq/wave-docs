##### REQ-5.1.6 HTTP/HTTPS for service APIs

WAVE provides comprehensive HTTP/HTTPS client capabilities enabling workflows to interact with RESTful APIs, web services, and HTTP-based endpoints with reliability features including automatic retry logic and comprehensive response handling.

**Plugin Purpose and HTTP Operations**: The HTTP plugin enables workflows to make HTTP and HTTPS requests to web services, RESTful APIs, and any HTTP-accessible endpoint. Primary capabilities include executing standard HTTP methods (GET, POST, PUT, DELETE, PATCH, HEAD, OPTIONS), sending request bodies with configurable content types (JSON, XML, form-encoded, binary), setting custom HTTP headers for authentication and content negotiation, handling response parsing for multiple content types, and extracting response data through structured output variables. The plugin serves critical testing scenarios including API endpoint validation, service health checking, webhook triggering, data retrieval from web services, and integration testing of HTTP-based microservices.

**Request Configuration and Headers**: The plugin accepts comprehensive request configuration enabling workflows to construct complex HTTP requests. Configuration parameters include the HTTP method selection, request URL with variable substitution support, request body content, content-type header specification for request body format indication, custom HTTP headers as key-value pairs enabling authentication tokens and custom headers, query parameters with automatic URL encoding, request timeout configuration with per-request overrides, and SSL/TLS verification settings. Request bodies are raw text, URL-encoded form fields, multipart form-data, or a single file. Headers support authentication schemes including Bearer tokens from variables, Basic authentication credentials from connection profiles, custom API keys, and OAuth tokens. The plugin provides structured input accepting headers and query parameters as dictionaries eliminating manual URL construction and header formatting complexity.

**Response Handling**: The plugin captures HTTP responses and returns raw response data without parsing, enabling workflows to extract and process response content using specialized plugins. Response data includes HTTP status code for success/failure determination, response headers as key-value dictionary, response body as raw text string without any parsing or transformation, detected content-type from response headers, response time metrics for performance monitoring, and final endpoint URL after redirects. All response bodies regardless of content type (JSON, XML, HTML, plain text, binary) return as raw strings, enabling workflows to assign the body to variables and process using specialized plugins such as JSON parser plugin for JSON content, XML plugin for XML content, or custom processing logic. This separation of concerns enables the HTTP plugin to focus exclusively on HTTP transport while delegating all format-specific parsing to dedicated plugins designed for those formats. The plugin supports configurable redirect following with maximum redirect limits preventing infinite loops.

**Authentication and Security**: The plugin integrates with WAVE's connection profile system enabling reusable authentication configuration across workflows. Authentication options include Bearer token authentication with tokens loaded from secure variables or profiles, Basic authentication with username/password from connection profiles, custom header-based authentication schemes (API keys, custom tokens), and OAuth token support through header injection. All credentials are loaded from secure storage and never logged or exposed in output variables. SSL/TLS verification validates server certificates by default preventing man-in-the-middle attacks, with configurable modes including strict verification requiring valid certificates, custom CA certificate specification for internal certificate authorities, and disabled verification for testing environments with self-signed certificates. CA certificates may be provided as a file path, loaded from a variable, or uploaded directly into the connection profile as a PEM-formatted multiline string. Each profile or plugin instance supports one CA certificate PEM which may contain a certificate chain (subCA + rootCA concatenated). All configured endpoints must present certificates signed by the specified CA, which is then the only certificate trusted; with no CA set, the block trusts the Additional Certificates and the public authorities chosen in Settings, and any trusted certificate, root or intermediate, completes a chain (REQ-4.5.16). A request made from the WAVE host follows the block's proxy choice, by default the Proxy setting in Settings (REQ-3.4.3.9, REQ-4.7.14). The block presents a client certificate for mutual TLS when the server asks for one. Request and response bodies never appear in the debug trace.

**Error Handling and Retry Logic**: The plugin implements comprehensive error detection and recovery for common HTTP failure scenarios. Connection-level errors including DNS resolution failures, connection refused, network timeouts, and SSL handshake failures are raised as exceptions enabling workflow error handling. HTTP-level errors including 4xx client errors and 5xx server errors are captured as response data rather than exceptions enabling workflows to validate error responses and implement custom retry logic through workflow try-catch blocks. The plugin distinguishes between retryable errors (connection failures, timeouts, 502/503/504 gateway errors) and non-retryable errors (authentication failures, 400 bad request, 404 not found) enabling intelligent retry behavior. Workflows configure retry policy through plugin parameters specifying maximum retry attempts, retry delay with exponential backoff, and HTTP status codes considered retryable. All error conditions produce structured output variables enabling workflow error handling and reporting.

**Connection Profiles for HTTP**: The plugin integrates with WAVE's connection profile system enabling reusable HTTP configuration across tests. HTTP profiles specify base URL eliminating repeated URL prefix configuration across plugin instances, default headers applied to all requests using the profile (authentication tokens, custom headers, user-agent), authentication credentials (username/password for Basic auth, API keys, Bearer tokens), SSL/TLS verification settings (CA bundle path, certificate verification mode), and timeout defaults for all requests using the profile. Profiles enable centralized management of API credentials, consistent authentication across test suites, environment-specific configuration without workflow changes, and simplified plugin configuration focusing on request-specific parameters rather than repeated connection setup.

**Performance and Resource Management**: The plugin implements efficient resource utilization for high-volume testing scenarios. Request timeouts ensure workflows don't block indefinitely on unresponsive services. Response body streaming enables processing large responses without loading entire content into memory. All connections are properly closed during plugin cleanup using guaranteed cleanup mechanisms ensuring no connection leaks during exceptions or cancellations.
