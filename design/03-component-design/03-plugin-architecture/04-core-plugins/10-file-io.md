##### REQ-3.4.1.10 File I/O operations (read/write/copy/move)

The File I/O block gives a workflow the file system operations a shell script gets from cat, tee, cp, mv, rm, stat, ls and mkdir -p: one block, eight operations, with the same path rules and the same outcomes wherever it runs.

**Purpose and Locus**: One block with eight operations - Read, Write, Copy, Move, Delete, Stats, List and Create folder - the file counterpart of the shell's cat, tee, cp, mv, rm, stat, ls and mkdir -p. The block runs on WAVE or, when placed inside a Remote Execution body, on the remote host through the pure-Python bundle. Both loci share one execution core and behave identically, with one difference: the `artifact://` and `testdata://` schemes name WAVE's own folders, so on the remote host they are refused at run time.

**Operation Model**: The operation is the only always-present setting, and it selects which other settings apply:

| Operation | Settings |
|-----------|----------|
| Read | Path |
| Write | Path, Content, If the file exists |
| Copy | Source, Destination, If the file exists |
| Move | Source, Destination, If the file exists |
| Delete | Path, Ignore missing |
| Stats | Path, Size, Checksum, Output format |
| List | Path, RegEx Pattern, Include subfolders, Size |
| Create folder | Path |

A single setting, "If the file exists", governs collisions: Write offers Replace it, Append to it and Fail the block (Replace it by default); Copy and Move offer Replace it and Fail the block. Read and Write handle UTF-8 text only, with no mode and no encoding setting; a leading byte-order mark is honored on Read, and a file that is not UTF-8 text fails Read with a message naming the file. Delete removes a file, or a folder with everything inside it, and its Ignore missing switch lets a cleanup step succeed when there is nothing to delete. Stats reports whether a path exists and what it is, adds the size when the Size switch is on (a folder's size is the total of everything inside it, at every depth) and a checksum (MD5, SHA-1, SHA-256 or SHA-512, empty for a folder) when one is chosen, and presents the result as individual outputs, as one map or as a one-row table per Output format. List returns a folder's entries as a table filtered by a regular-expression Pattern matched against each entry name (empty lists everything), at one level or at every depth with Include subfolders, with sizes when the Size switch is on, a folder row carrying the total of everything below it. Create folder makes the folder named by Path together with its missing parents; an existing folder is not an error.

**Path Resolution**: Path, Source and Destination take one of four forms: an `artifact://` reference, resolved from the run's artifact directory; a `testdata://` reference, resolved from the running test's own test data folder (read-only); an absolute path; or a relative path. A plain path resolves where the block runs: on WAVE a relative path starts at the home folder of the operating-system user the WAVE server runs as, the base every WAVE-side block without a working directory setting shares, and on the remote host it starts at the SSH user's home folder, where the worker starts. A `..` segment is accepted in every form and on every locus and is followed wherever it leads, including out of the folder a scheme names; a plain path is made absolute and its `..` segments collapsed before the disk is touched, the same on WAVE and on the remote host, so a `..` after a folder that does not exist still resolves; a scheme reference is resolved on its real location, with symbolic links followed. A scheme reference starts from its own folder however many slashes follow the scheme. A bare `artifact://` - or any `artifact://` reference that resolves to that folder itself, such as `artifact://.` - names the run's artifacts folder: Delete, and Move with it as the Source, refuse it before anything touches the disk, as does every block that deletes or moves a path by reference; every other operation works on the folder, so List and Stats report on it, Copy with it as the Source copies the whole folder, Read fails as it does on any folder and Write fails as it does over any existing folder. A path inside the folder, `..` segments included, is not affected. A bare `testdata://` names the running test's test data folder: List and Stats report on it, Copy with it as the Source copies the whole folder, Read fails as it does on any folder, and a write, move or delete of it is refused as read-only. Test Data is read-only by location: a write, move or delete whose resolved target lies anywhere inside the Test Data storage area - any test's folder, not only the running test's - is refused however it was addressed. There is no system-directory blocklist: on WAVE the block runs with the server's own permissions, exactly as the Shell Script block does; on the remote host it runs with the SSH user's. On the remote host a `testdata://` or `artifact://` path is refused at run time, before anything touches the disk, whether it was typed, read from a variable or an expression, or passed into a Function the body calls; nothing is created on the remote host. The test saves, imports and validates with such a path, and the Browse control is absent inside a Remote Execution body.

**Outputs**: Outputs are per operation, and the block exposes only the rows the chosen operation produces. Read yields Content. Stats yields Exists, Type (file, folder, or empty when the path is missing), Modified, Size when the switch is on and Checksum when one is chosen - or the same values as one Stats map or a one-row Stats table. List yields Entries and Count. Write, Copy, Move, Delete and Create folder have no outputs. Modified is ISO-8601 UTC. There is no path output and no success flag: a failed operation fails the block, like every other system block.

**Semantics**: Destination is always the full target path including the new name; nothing lands "inside" a folder by default. A file destination that is an existing folder fails, for Write as for Copy and Move. Copying a folder onto an existing folder with Replace it merges: files inside are replaced, other entries are kept; Fail the block refuses whenever the destination exists. Move follows Copy's rules and then removes the source; on one file system it is a rename. Write, Copy, Move and Create folder always create missing parents. Stats never fails on a missing path: it reports that the path does not exist. Pattern matches entry names, not paths, and folders are matched too; Entries are sorted by path, with paths relative to the listed folder. Symbolic links are followed on read and never listed.

**Execution Engine**: A synchronous standard-library core implements every operation and is shared by the WAVE-side plugin and the remote bundle, so both loci apply collision rules and produce results identically. On WAVE the plugin resolves the schemes before the core runs; on the remote host the core refuses a scheme before any other step. On WAVE the plugin runs the core off the event loop so a large copy or checksum never stalls other work.

**Error Handling**: A failed operation fails the block with a message that names the path and, where one exists, the setting that would change the outcome: a file or folder that is not there (Read, List, and the source of Copy and Move); a file that is not UTF-8 text (Read); a destination that is an existing folder (Write, Copy, Move); a target that exists while "If the file exists" is Fail the block (Write, Copy, Move); a write, move or delete into the read-only Test Data area; nothing to delete while Ignore missing is off (Delete); a Delete or a Move source that names the run's artifacts folder itself; a file where Create folder expects a folder; and, on the remote host, a `testdata://` or `artifact://` path, refused with a message that names the scheme and asks for an absolute or relative path on the remote host.
