##### REQ-3.4.1.17 Log plugin (write messages to execution log with configurable level)

The log plugin enables test designers to write explicit messages to the execution log with configurable severity levels, providing workflow progress markers, diagnostic output, and audit trail entries.

**Plugin Purpose and Use Cases**: The log plugin emits explicit log entries at designated workflow points. Primary use cases include progress markers for workflow milestones, diagnostic output displaying computed values or variable states, status messages reporting validation outcomes, and audit trail entries for compliance. Unlike implicit plugin logging (internal diagnostics), log plugin messages are user-authored content appearing prominently in execution artifacts.

**Configurable Log Level**: The plugin accepts a level parameter specifying message severity. Supported levels follow the standard hierarchy: DEBUG for verbose diagnostics, INFO for general progress (default), WARN for important notices, ERROR for significant problems, and FATAL for critical issues. The level determines positioning in filtered log views and attention level during monitoring.

**Message Content and Expression Support**: The plugin accepts a required message parameter containing text to write. When the expression toggle is enabled, the message is a Python expression evaluated at runtime - typically an f-string for dynamic content (e.g., `f"Request to {endpoint} returned {status_code}"`). In literal mode, the message is static text written as-is. An expression message takes a value of any type: text is written as it is, and any other whole value is written in WAVE's print form - `true` or `false`, a number as written, and a list, map or table as JSON text (see REQ-3.1.3.23). Every other text setting still refuses a value of the wrong type. The message is a data field: a null message, and any null `{{ }}` piece in it, prints `null`, the one field where a null piece prints instead of failing. Text Python builds itself inside an expression, such as an f-string, still writes Python's own `None` (see REQ-3.1.3.23).

**Execution Artifact Integration**: Messages appear in execution artifacts with standard metadata: timestamp, log level, source context, and resolved content. Log entries are visually distinguishable from framework diagnostics, making workflow messages easy to locate.
