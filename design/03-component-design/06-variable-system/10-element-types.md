### 3.6.10 Declared Element Types

##### REQ-3.1.3.19 Declared element types for array and map values

Every item of an array and every value of a map carries a declared type, the same way a scalar variable carries its declared type and a table carries the types of its columns. The declared type is chosen by the author, stored with the value, and decides what the element is at run time. It is never taken from how the element's text looks: a zip code `02134`, a version `1.10` or an application name `2024` is text for as long as its element is declared text.

**Element types**: the six types an element can declare are string, integer, float, boolean, array and map. A nested array or map is itself typed by its structure: its leaves are numbers, text, booleans or further structures exactly as written, so a nested number stays a number and nested quoted text stays text.

**Stored beside the value**: an array or map value keeps its elements' declared types in a companion record held where the value's own declared type is held - beside the value of a variable declaration at every scope (test, Function, suite, regression, system), beside a Function parameter's default, beside a profile field's value in each environment, beside a Variable Setter row, and beside a block setting that accepts typed entries. For a map the record names each key's type; for an array it lists each item's type in item order. The value itself stays a plain array or map, so every reader that does not need the types sees the same value as before. Numbers inside the value are held as their exact text, as scalar numbers are (REQ-3.1.3.14), so a large integer or a float such as `1.0` keeps its exact digits through every hop.

**An element with no declared type**: a value may carry no record at all, for instance one written by a client that sends none, and a record may omit an element. Each such element is typed by its stored shape: a stored boolean is a boolean, a stored structure (or its exact structural text) is an array or map, and everything else is text.

**Every surface keeps the types**: the variable editors (the variable window and its "Edit value" editor, the entity variable tables, the Variable Setter, profile fields, typed block settings; the watcher shows the same record), saving and loading, the run-time override of a paused run's value, import and export of every entity, backup and restore, and recipe authoring and readback all carry the record unchanged. Changing only an element's declared type is a real edit: it saves, and it changes the run-time value.

**Run-time realization**: one realization rule serves every scope, identical to the scalar rule. A whole-number element becomes an exact integer; a float element becomes an exact decimal with the uniform 28-significant-digit precision, so arithmetic with it stays exact and mixes with plain numbers; a boolean is a boolean; a string is the text unchanged, whatever it resembles; an array or map element becomes its structure, with nested floats and integers exact. Text that is not a valid value of its declared type stays text rather than failing the realization, as a scalar's does, and the editors and the server's save check refuse it before it is saved (REQ-3.1.3.14 one number rule). A null item or map value stays null and fits any declared element type (see REQ-3.1.3.20).

**Plugin boundary**: when a block setting's typed entries reach a plugin, float elements, top-level or nested, are reduced to platform floating-point numbers at the call, the same boundary rule a float parameter follows (REQ-3.1.3.14). The rule holds however the entries were written: literal rows, a row whose expression yields an exact decimal, or the whole setting supplied by a bound profile's field. The setting's stored value is unaffected.

**Run-time views**: a value read from a running session reports its elements' real run-time types, so a paused run's current value shows a float element as a float and a whole number as a whole number, and a current-value override declares its elements' types just as a saved value does. A whole number beyond the range a browser holds exactly is read as its exact digits, so viewing or overriding a current value never rounds an element nobody edited.

**Secrets**: a secret array or map hides its elements' declared types together with its value on every read and every masked export, so a masked secret names no key and counts no element. A save that sends the masked value back keeps the stored value and its element types together; a Variable Setter row marked secret keeps its element types sealed together with its value at rest, so no read of the Test names its keys or counts its elements, and a masked export leaves them out the same way.

**Editing**: every row of an array or map editor shows its declared type and offers the six types. A row's type changes only when the author picks one: typing digits into a row never turns it into a number. Typing `true` / `false` or an opening bracket into a row whose type is not yet declared selects boolean, array or map. A row whose type was declared - stored with the value or picked in the editor - keeps it while its text is edited, and text that does not fit the declared type is flagged. The raw JSON view types elements by JSON syntax: a quoted value is text and an unquoted number is a number.

**Typed block settings**: a block setting that feeds a system taking typed values declares that its entries are typed; the SQL block's Driver options is one (REQ-3.4.1.6). Its rows show the type picker beside the per-row expression toggle; an expression row shows no type, because its expression's result is the value. Settings whose values are always text for the system they feed - HTTP headers and query parameters, the HTTP retryable status codes, environment entries, SQL bind values - stay text-only and show their fixed type as a read-only pill: a map setting's values and a list setting's items are saved as text.

**Validation**: a stored record must match the value it describes: a map's record is a mapping of keys to element types, an array's record is a list, and each named type is one of the six. A record on a value that is neither an array nor a map, or a type outside the six, is rejected where the value is saved. A recipe's float element must be a finite number, whether its type is declared or taken from the YAML.

**Nested items**: items nested inside a List or Map item take their type from the stored value itself, so a whole Float is written with `.0` (`3.0`) and an Integer without it; the editors show and change those types at every nested level.
