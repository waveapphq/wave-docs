### 3.8 MCP Server

WAVE embeds a Model Context Protocol (MCP) server that lets AI assistants act as test engineering clients. Any MCP-capable client - a coding agent on a developer workstation, or a locally hosted LLM stack inside an air-gapped deployment - connects to a WAVE-served endpoint and gains a curated set of tools for building tests, organizing them, running them, and diagnosing failures. WAVE itself contains no AI: it offers the socket and the tools, and the intelligence lives entirely in whatever client the deployment chooses. This preserves the platform's air-gapped posture while giving regulated environments with local LLMs the same assisted-authoring capability as connected ones.

**The assistant is an ordinary client.** Every action taken through the MCP endpoint flows through the same services, the same validation pipeline, and the same persistence rules as the web UI. There is no privileged path: a definition the UI would reject is rejected over MCP with the same errors, executions started over MCP are ordinary tracked executions attributed to the assistant client and visible in the execution history, and secret masking policy applies to MCP responses exactly as it applies to UI surfaces. A team lead can always audit what the assistant did using the same records that cover human activity.

**Tool families.** The surface is small and deliberate, organized in four families. Discover exposes read-only catalogs and listings: the block catalog with each block's declared settings, the Functions library, tests, suites, regressions, environments, profiles, system and global variables, and past executions. Author creates and amends entities: tests through the recipe format, plus suites, regressions, profiles, and system and global variables. Run starts and monitors executions of tests, suites, and regressions. Report produces the structured failure report for an execution and retrieves generated run reports.

**The recipe.** Tests are authored through a purpose-built recipe format rather than the canvas-native document. A recipe describes a test the way an engineer would narrate it - steps in order, branches and loops nesting their contents - and WAVE compiles it into a genuine canvas test, generating all wiring and layout itself. The client LLM never manipulates canvas mechanics, which removes the entire class of malformed-graph and layout failures that free-form definition authoring produces. The MCP serves the recipe format guide and worked examples as reference material, so any client learns the format from WAVE itself.

**Session ownership.** The workbench follows a single-active-session ownership model: one holder mutates a session at a time, and every other viewer mirrors it live in a read-only state with a visible way to take over. The MCP participates as an ordinary holder, which is what enables watch-mode authoring: the user observes the assistant building a test block by block on their own canvas and can take control at any moment.

The subsections that follow describe the recipe format, compilation and automatic layout, the tool surface, secret handling, session ownership and live mirroring, and configuration and deployment.
